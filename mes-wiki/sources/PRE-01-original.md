> **文档性质**：开发前预研分析（产品/技术方案层面，不含代码级实现）  
> **编制单位**：天津市科美通科技发展有限公司

## 一、预研背景与目标

### 1.1 问题来源

阶段一Demo中预置了线束行业标准7工序（裁线下线 → 压接 → 预装 → 总装 → 导通测试 → 外检 → 包装入库），作为"行业模板"帮助客户快速理解。但如果系统层面把这7道工序**写死在代码或固化的数据结构里**，会面临致命问题：

- 不同线束细分行业（汽车/家电/工业）工艺路线**本质不同**
- 同一工厂不同产品线工艺路线**不同**
- 同一产品不同客户有**特殊工艺要求**
- 客户工艺会**持续演进**（新增工序、合并工序、调整顺序）
- 实施新客户时每次改代码 → 变成**项目外包**而非产品

### 1.2 预研目标

- 明确"工序流程灵活配置"到底要配置什么、配置到什么粒度
- 确定配置能力的分级演进路线（避免一次性过度设计）
- 识别关键设计决策点和风险
- 给出阶段一落地建议，同时为阶段二三预留架构空间

### 1.3 预研范围

| 在范围内 | 不在范围内 |
|---------|-----------|
| 工序流程的数据模型设计思路 | 具体数据库表结构/代码实现 |
| 配置能力的分级定义 | 可视化编辑器的前端技术选型 |
| 与各模块的联动影响 | 排程算法/规则引擎的实现 |
| 行业差异调研与配置场景 | 第三方低代码平台的集成方案 |

## 二、线束行业工艺差异现状

### 2.1 三大线束细分行业的工艺对比

| 维度 | 汽车线束 | 家电线束 | 工业线束 |
|------|---------|---------|---------|
| **典型工序数** | 7-9道 | 4-5道 | 5-7道 |
| **标准流程** | 裁线→压接→预装→总装→导通→外检→包装 | 裁线剥头→压接→穿胶壳→导通→包装 | 裁线→压接→焊接→穿壳→测试→包装 |
| **独有工序** | 防水栓穿装、截面分析、100%电测 | 锡焊、注塑成型 | 热缩管、屏蔽层处理 |
| **压接管控** | 全过程监控（压力-位移曲线+剖面检测） | SPC统计控制+首件检验 | 介于两者之间 |
| **检验深度** | 100%导通+耐压+绝缘，全回路 | 导通+耐压（安全强制） | 导通+绝缘+耐压 |
| **追溯要求** | IATF16949全生命周期 | ISO9001+UL认证 | ISO9001 |
| **物料种类** | 几十到上百种 | 3-5种 | 10-20种 |
| **典型客户** | 主机厂/Tier1 | 家电品牌 | 工业设备/OEM |

### 2.2 工艺差异的5种典型场景

| 场景 | 描述 | 配置需求 |
|------|------|---------|
| **行业差异** | 汽车线束有"防水栓穿装"工序，家电没有 | 增/删工序 |
| **产品差异** | 同一工厂，A产品有焊接工序，B产品没有 | 不同产品不同路线 |
| **客户差异** | 同一产品，客户A要求截面分析，客户B不要求 | 同产品多路线版本 |
| **产线差异** | 工厂有自动线（裁线+压接一体）和手工线（分开），同产品走不同工序编排 | 工艺路线可复制可调整 |
| **试产/量产** | 试产时增加"首件全检"工序，量产后取消 | 临时路线+版本切换 |

### 2.3 关键洞察

> 线束行业的工艺差异**不是随机变化**，而是有规律的"模板+变体"模式。7道标准工序是稳定的骨架，差异集中在：
> 1. 是否有焊接/注塑/热缩管等**特殊工序**
> 2. 检验工序的**深度和粒度**不同
> 3. 是否有**防水栓/截面分析**等汽车专属工序
> 4. 是否走**自动线或手工线**的不同设备路径

这意味着——不需要做成"万能流程引擎"，而是做"**行业模板 + 有界配置**"。

## 三、配置维度分析

工序流程配置可拆解为4个层次，每个层次的配置对象和粒度不同：

### 3.1 工序级配置（定义"有哪些工序"）

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 工序编码 | 全局唯一标识 | OP01_CUT, OP02_CRIMP |
| 工序名称 | 显示名称 | 裁线下线 |
| 工序类型 | 决定行为模式 | 加工工序 / 检验工序 / 包装工序 |
| 是否关键工序 | 影响首检/追溯要求 | 压接=关键，包装=非关键 |
| 工序说明 | 工艺要求描述 | 裁线长度公差±0.5% |
| 关联SOP | 作业指导书 | PDF/视频链接 |

### 3.2 流转级配置（定义"工序怎么串"）

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 工序顺序 | 线性/分支/并行 | 裁线→压接→预装（线性） |
| 前置工序约束 | 本工序开工需上工序完工确认 | 压接开工需裁线完工 |
| 可跳过条件 | 某些产品可跳过特定工序 | 家电线束跳过防水栓 |
| 并行工序 | 多工序可同时进行 | 预装与总装可并行 |
| 返工回流 | 不良品返回哪道工序 | 压接不良→回压接 |

### 3.3 工序内配置（定义"工序怎么做"）

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 扫码点设计 | 本工序扫什么码、校验什么 | 压接：端子+导线+防水栓+模具四码 |
| 防错规则 | 物料/BOM/工艺校验逻辑 | 端子编码=BOM端子编码 |
| 检验项 | 首检/巡检/完工检的项目 | 压接高度、拉力值 |
| 数据采集字段 | 需录入的数据项 | 实际完工数、不良数 |
| 异常上报类型 | 允许上报的异常类别 | 设备故障、缺料、来料不良 |
| 作业人员资质 | 是否需技能认证 | 压接需持证上岗 |

### 3.4 工单级配置（定义"这次怎么做"）

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 工艺路线版本 | 引用哪个模板版本 | V3.2 |
| 临时调整 | 工单内增删工序（试产） | 增加"首件全检" |
| 批次粒度 | SN级/批次级追溯模式 | 汽车线束=SN级 |
| 客户特殊要求 | 客户追加的检验项 | 客户A要求拉力≥80N |

## 四、配置能力分级方案

不是一步到位做"万能流程引擎"，而是分4级递进。每级独立可交付、有明确价值，避免过度设计。

### L1 · 行业模板预置（阶段一MVP）

**能力**：系统预置线束行业标准7工序模板，客户开箱即用。

| 项 | 说明 |
|----|------|
| 配置方式 | 代码/数据脚本预置，不提供修改界面 |
| 适合客户 | 工艺与标准模板基本一致的线束厂 |
| 工序定义 | 固定7道，含扫码点/检验项/防错规则 |
| 流转规则 | 线性顺序，强制工序间完工确认 |
| 限制 | 客户工艺有差异时需开发改代码 |

**价值**：2周内让客户上线，用"行业模板"换取实施速度。  
**风险**：第2个客户工艺不同时就要重构。

### L2 · 有限配置（阶段一迭代）

**能力**：工艺工程师通过表单界面增删工序、调整顺序、开关扫码点，不需要改代码。

| 项 | 说明 |
|----|------|
| 配置方式 | 表单式配置界面（增删改/拖拽排序） |
| 适合客户 | 工艺与标准模板有少量差异的线束厂 |
| 工序定义 | 可新增自定义工序，设置属性 |
| 流转规则 | 线性顺序为主，支持"可跳过"标记 |
| 扫码点 | 可开关（本工序是否扫码）、可调整防错物料清单 |
| 版本管理 | 工艺路线版本号，新版本不影响在制工单 |
| 限制 | 不支持分支/并行/条件路由 |

**价值**：实施新客户时工艺工程师自行配置，不依赖开发。  
**关键设计点**：在制工单锁定旧版本，新版本只对新工单生效。

### L3 · 可视化路线编辑器（阶段二）

**能力**：图形化拖拽编排工艺路线，支持分支和并行工序。

| 项 | 说明 |
|----|------|
| 配置方式 | 图形化拖拽编辑器（类似流程图） |
| 适合客户 | 多产品线、工艺差异大的中大型线束厂 |
| 流转规则 | 支持分支（条件跳过）、并行（多工序同时）、回流（返工） |
| 版本管理 | 完整版本树，支持对比/回滚 |
| 预览模拟 | 配置后可"模拟运行"验证路线 |
| 联动 | 与设备管理关联（工序绑设备类型） |

**价值**：工艺工程师"画"出工艺路线，所见即所得，配置效率提升3-5倍。

### L4 · 规则引擎动态路由（阶段三+）

**能力**：同一产品不同工单可走不同工艺路线，由规则自动路由。

| 项 | 说明 |
|----|------|
| 配置方式 | 规则引擎配置（条件-动作） |
| 典型场景 | 试产工单走全检路线，量产走抽检路线 |
| 路由条件 | 工单属性（客户/产品类型/批量/优先级） |
| 动态调整 | 工单执行中可根据异常动态改变后续路线 |
| 限制 | 复杂度高，需积累足够工艺数据后才有意义 |

**价值**：真正实现"柔性制造"，但**过早追求L4是过度设计**。

## 五、关键设计决策

### 5.1 模板 vs 实例

| 方案 | 说明 | 利弊 |
|------|------|------|
| **模板→实例**（推荐） | 工艺路线模板（产品级） → 工单创建时实例化为工单工艺路线 | 可追溯每张工单的实际路线；模板变更不影响在制工单 |
| 工单直接引用模板 | 工单只存模板ID，不存实例 | 模板改了历史工单追溯链变；简单但不可靠 |
| 纯实例无模板 | 每张工单独立配工艺 | 灵活但维护成本极高，工艺不统一 |

**建议**：采用"模板→实例"模式。工单创建时复制模板为实例，实例不可改（除临时调整需审批）。

### 5.2 流转规则：强制顺序 vs 可跳转

| 规则 | 说明 | 适用场景 |
|------|------|---------|
| **强制顺序+完工确认**（推荐阶段一） | 上工序未完工确认，下工序扫码开工被拦截 | 防止跳工序/漏工序，质量追溯完整 |
| 可跳过（需标记原因） | 某产品跳过防水栓工序，扫码时记录跳过原因 | 灵活但增加追溯复杂度 |
| 可回退 | 返工回上工序 | 返工场景必需 |

**建议**：阶段一默认强制顺序，L2级配置支持"可跳过"标记（必须填原因），返工回流单独走返工工单。

### 5.3 版本管理策略

```
工艺路线模板 V1.0（上线）
  ├── V1.1（增加截面分析工序，不影响在制工单）
  │     ├── 在制工单 WO-001 仍走 V1.0
  │     └── 新工单 WO-002 走 V1.1
  └── V2.0（大版本：合并预装+总装，需评审）
        └── 评审通过后生效，旧版本归档
```

| 决策点 | 建议 |
|--------|------|
| 版本号规则 | 主版本.子版本（V1.0 → V1.1 → V2.0） |
| 小版本 | 增删工序/调整顺序 → V1.1, V1.2 |
| 大版本 | 工艺架构性变更 → V2.0，需评审 |
| 在制工单 | 锁定创建时的版本，不受模板变更影响 |
| 回滚 | 支持回滚到任意历史版本，但需记录原因 |

### 5.4 在制工单兼容（最关键的工程问题）

这是配置灵活性最大的风险点。客户改了工艺路线，正在生产的工单怎么办？

| 策略 | 说明 | 建议 |
|------|------|------|
| **快照锁定**（推荐） | 工单创建时复制模板为快照，模板变更不影响在制工单 | 阶段一必做 |
| 强制升级 | 在制工单强制切到新版本 | 不推荐，可能造成数据混乱 |
| 人工迁移 | 提示有在制工单，人工确认后逐个迁移 | 可选，适用于大版本升级 |

**建议**：阶段一就实现快照锁定机制——这是数据模型的基础设计，后补代价极大。

### 5.5 工序合并/拆分

线束行业常见场景：自动线把"裁线+压接"合并为一个工序节点，手工线分开。

| 方案 | 说明 |
|------|------|
| 支持工序合并 | 配置时可将多道工序标记为"合并执行"，扫码一次覆盖多工序 |
| 支持工序拆分 | 一道工序拆为子工序（如压接拆为：备料→压接→自检） |

**建议**：阶段一L1级暂不支持（用预置模板覆盖），L2级支持工序合并/拆分的标记，L3级在可视化编辑器中原生支持。

## 六、与各模块的联动影响

工序流程配置是"中枢"，改一处影响全局。各模块必须从设计之初就考虑配置驱动。

| 模块 | 配置驱动点 | 阶段一需做的 |
|------|-----------|-------------|
| **工单管理** | 工单创建时选择产品→自动带出工艺路线模板→实例化 | 引用模板ID+版本号，生成快照 |
| **扫码流转台** | 扫码时按配置的扫码点校验，按流转规则拦截跳工序 | 从工单工艺实例读取工序和扫码点配置 |
| **质量管理** | 检验项跟随工序配置，不良代码库按工序类型预置 | 工序-检验项关联表 |
| **批次追溯** | 追溯链路按工单实际走的工艺路线展开（不是固定7工序） | 追溯查询读取工单工艺实例 |
| **生产看板** | WIP分布按工单工艺实例的工序节点统计 | 看板渲染动态读取工序清单 |
| **基础数据** | 工艺路线模板维护入口 | 模板CRUD + 版本管理 |

**关键原则**：所有模块**不写死工序清单**，统一从"工单工艺实例"读取。

## 七、风险与约束

### 7.1 过度设计风险（最大风险）

> "我们才1个客户，就做了支持任意流程编排的规则引擎" — 这是典型的过度设计。

| 风险 | 表现 | 防范 |
|------|------|------|
| 配置灵活度 vs 实施复杂度 | 越灵活→配置越复杂→实施越慢→客户体验越差 | L1+L2先跑通5-10家客户，积累真实工艺差异样本再上L3/L4 |
| 配置错误影响生产 | 工艺工程师配错路线→工人扫码被拦截→停产 | 配置预览/模拟运行 + 审批流程 + 灰度发布 |
| 培训成本 | 配置界面太复杂→工艺工程师不会用 | L2表单式≤10个字段，L3可视化编辑器需配套培训 |

### 7.2 数据一致性约束

| 约束 | 说明 | 对策 |
|------|------|------|
| 在制工单兼容 | 模板变更不能影响在制工单 | 快照锁定（必做） |
| 追溯链完整 | 工艺路线变更后，历史追溯链不能断 | 追溯读取工单快照 |
| 版本可追溯 | 任意时刻能回答"这张工单当时走的是什么工艺" | 工单绑定版本号+快照 |

### 7.3 行业约束

| 约束 | 影响 |
|------|------|
| IATF16949要求工艺变更评审 | 大版本变更需有评审记录，系统需支持 |
| 客户审核要求工艺冻结 | 试产→量产切换时工艺需"冻结"，系统需支持冻结状态 |
| 跨工厂工艺不一致 | 多工厂客户需支持工厂级工艺路线模板 |

## 八、产品节奏建议

### 8.1 阶段一落地建议（L1+L2）

| 优先级 | 做什么 | 不做什么 |
|--------|--------|---------|
| **P0 必做** | 预置7工序模板 + 工单创建时实例化为快照 + 版本号管理 | 不做可视化编辑器 |
| **P1 应做** | 表单式工序增删改 + 顺序拖拽调整 + 扫码点开关 | 不做分支/并行 |
| **P2 可做** | 工序合并标记 + 可跳过工序（需填原因） | 不做规则引擎 |
| **不做** | 可视化拖拽编辑器 / 条件分支 / 动态路由 | 留给阶段二三 |

### 8.2 数据模型设计原则（阶段一就预留）

虽然不写代码，但数据模型设计原则需在预研阶段明确：

1. **工序定义表**独立于工艺路线——工序是"积木"，路线是"拼法"
2. **工艺路线表**存工序引用+顺序+流转规则，不存工序定义本身
3. **工单工艺实例表**存工单ID+路线快照（JSON/序列化），与模板解耦
4. **版本字段**在模板和实例上都要有
5. **扩展字段**预留（设备绑定、参数下发、SOP关联）——阶段二三用

### 8.3 阶段二/三演进路径

| 阶段 | 配置能力 | 前置条件 |
|------|---------|---------|
| 阶段二 | L3 可视化路线编辑器 | L1+L2跑通5+客户，积累工艺差异样本 |
| 阶段三 | L4 规则引擎（条件分支） | 设备联网完成后，工艺参数可自动判断分支条件 |
| 远期 | 跨工厂工艺模板管理 | 多工厂客户出现后 |

| 参考产品/方案 | 配置能力 | 借鉴点 |

| **迈斯MES**（线束/锂电池行业） | 支持工序跳过/重复/并行，零代码工艺引擎 | 行业模板+自由配置结合，"项目自由配置工艺" |
| **Hi MES**（汉思） | ISA-95工厂建模，图形化工艺路线配置 | 图形化界面+层级结构+拖拽操作 |
| **TMom**（开源） | AntV X6可视化工艺路线设计器 | 前端图形库选型参考、节点图形式展示 |
| **Tulip**（国际No-code MES） | 可视化app builder，step-by-step执行 | 工序作为screen，配置即界面 |
| **CodeWave/活字格**（低代码平台） | 可视化拖拽+强类型校验 | 低代码思路，但可能过度灵活 |

**关键结论**：行业头部MES全部支持工艺路线可配置，但都经历了"模板预置→有限配置→可视化编辑"的演进。没有一家一开始就做规则引擎。

## 十、结论与建议

### 10.1 核心结论

1. **工序流程不能写死**——这是正确的产品方向，行业头部MES全部支持配置
2. **但也不能一步到位**——L4规则引擎对阶段一是过度设计
3. **阶段一的正确姿势**：L1预置模板 + L2有限配置 + 快照锁定 + 版本管理
4. **数据模型要从一开始就设计好**——工序/路线/实例三层分离，扩展字段预留
5. **所有模块配置驱动**——扫码台/看板/追溯/质量都从工单工艺实例读取，不写死工序
